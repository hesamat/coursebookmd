## Present mode in a separate window (second-display aware)

Replace in-page present mode with a dedicated presentation window that auto-places on a second display (Chromium) and auto-fullscreens there (F-key fallback). The opener window keeps editor/TOC; the popup is a small, self-contained viewer built from a new Vite multi-page entry — it does not boot the full app.

### New files

**1. `present.html`** (project root, second Vite entry)
Minimal popup skeleton linking the same 5 stylesheets as `index.html`; body: `.preview-pane > #content`, `.chapter-nav` (prev/next chapter buttons), `.overlay` (current/next/progress/hints), a small "waiting for content" placeholder, and a fullscreen-hint chip. Loads `/src/present/popup-main.js`.

**2. `src/present/popup-main.js`** — popup bootstrap

- Adds `presenting` to its own `<body>`; copies `data-theme`/`data-palette` attributes from `window.opener.document`.
- Waits for opener transfer: `{ type: "cbmd:present-data", chapterTitles, currentChapterIdx }` (metadata only). Validates `event.origin === location.origin` and `event.source === window.opener`.
- Instantiates `SectionNavigator(contentEl, pane)` directly (public API supports this), sets `navigator.onNavigate` → overlay update (current/next/progress, "Next chapter: <title>" from `chapterTitles`).
- Own keydown handler mirroring the present-mode key map: Arrows/Space/PageUp/PageDown/Home/End navigate, `S` spotlight, `F` fullscreen toggle, `Escape` exits fullscreen then closes the window.
- Chapter switching popup-side (no opener round-trip): `.coursebook-section` siblings, `#overview` = idx -1; toggle `.active`, scroll top, `navigator.setup()`, prev/next buttons + labels from `chapterTitles`.
- Fullscreen: attempt `requestFullscreen()` when data arrives; if rejected (no user activation in popup), show the hint chip; chip click and `F` both request it (real gesture). Hide chip on `fullscreenchange`.
- Persists its own window bounds to `localStorage` on move/resize (debounced) for fallback placement next time.

**3. `src/present/popup-helpers.js`** — pure functions (unit-testable): overlay text computation (current/next/next-chapter/end-of-coursebook), chapter list resolution from section ids/titles.

**4. `src/controllers/present-window-controller.js`** — opener side, deps `{ state, chapterRenderer }`, follows the existing deps-injection controller pattern:

- `openPresentWindow()`: if popup alive → focus + re-push content; else:
  - Open `about:blank` popup **synchronously in the click gesture** (popup-blocker safe), then `await getScreenDetails()` (Chromium; triggers the one-time permission prompt): pick target screen = first non-current external screen, else first non-current, else current; `moveTo/resizeTo` to its `availLeft/Top/Width/Height`, then navigate to `present.html`.
  - No API (Safari/Firefox) or permission denied: restore last bounds from `localStorage`, else centered ~90% window.
- On popup `cbmd:present-ready`: deep-clone `state.contentEl`, `popup.document.adoptNode(...)` into popup `#content` (DOM adoption only — **no `innerHTML` anywhere**, per repo rule; blob: image URLs are origin-scoped and keep working), copy theme attrs, send metadata (chapter titles, current idx, current section idx within chapter, standalone vs coursebook mode).
- Clears the stored popup ref on popup close.

### Modified files

**5. `src/controllers/presentation-controller.js`** — remove `enterPresent`/`exitPresent` and the `fullscreenchange` exit hook; `state.presentBtn` click and the `Cmd/Ctrl+P` shortcut call the injected `openPresentWindow()` (new dep, wired in app.js — controllers never import each other). Keep: standalone fullscreen toggle button, normal-mode keyboard/section navigation (which deliberately works in both modes), `E`/`I` shortcuts. The `S` spotlight shortcut stays gated on presenting (now only meaningful in the popup, which handles its own keys). Opener `updateOverlay` stays (inert without `body.presenting`; chapterRenderer depends on it).

**6. `src/app.js`** — compose `wired.presentWindow = createPresentWindowController({ state, chapterRenderer })`; pass `openPresentWindow` into the presentation controller deps.

**7. `vite.config.mjs`** — add `build.rollupOptions.input` for `index.html` + `present.html`.

**8. `e2e/present-mode.spec.js`** — rewrite for the popup flow: `#presentBtn` opens the popup page (headless has one screen → fallback placement path), assert `presenting` class + overlay + content sections in popup, arrows move sections and update overlay, chapter next/prev switches `.active`, `F`/Escape/window-close behavior.

**9. New unit tests `src/__tests__/present-window.test.js`** — screen-pick logic, placement features/bounds restore, popup-ref cleanup, metadata payload; `popup-helpers` overlay/chapter resolution (jsdom, mock `window.open`/`getScreenDetails`/`localStorage`).

**10. `README.md`** (user-facing: new present flow, second-display auto-placement + one-time browser permission, macOS "Displays have separate Spaces" note, F fullscreen, Esc/close to exit) and **`AGENTS.md`** (source-structure list: `present/` popup entry, `present-window-controller`).

### Edge cases handled

- Popup-blocker: blank popup opened synchronously, positioned/navigated async.
- Permission denied / Safari: remembered-bounds or centered fallback window; drag-to-screen still works.
- Standalone (single .md) mode: no chapter nav, root-level section wrapping.
- Opener re-renders after edits: stale popup acceptable in v1; clicking Present again focuses + re-pushes fresh content.
- Auto-fullscreen blocked: hint chip + F key.
